不是聊天框。

SEECODER 将自然语言任务转换为可审计的本地执行闭环：接收目标 → 管理上下文 → 请求模型 → 解析意图 → 校验工具 → 执行并回填 → 验证或停止。模型提出下一步，程序掌握权限、事实和终止权。

02 / LAYERS

四层结构，
一个控制平面。

展示层不执行工具，模型不越过策略层。所有动作都经过本地 Runner 的同一条控制路径。

LAYER 01
desktop/swiftui · desktop/electron

交互与审阅面

接收用户任务，显示消息、折叠推理、运行轨迹、审批卡片和文件 diff；只消费事件，不直接修改工作区。

VIEW
LAYER 02
cli.py · JSONL protocol v3

事件与会话桥

以 session_id、run_id、sequence 传递有序事件，让桌面端可以断线重连、区分轮次并恢复状态。

EVENT
LAYER 03
runner.py · session.py · context.py

AgentRunner 控制平面

维护历史、上下文预算、工具策略、审批、取消、超时、错误阈值和唯一终态，是整个 Agent 的状态机。

CONTROL
LAYER 04
tools/ · changesets.py · trace.py

本地能力与证据层

文件、搜索、命令、Git 和子代理都通过注册表执行；工作区边界、变更基线和脱敏 trace 在这里落地。

ACT
INVARIANT任何模型输出都不会直接变成副作用。

它必须先变成结构化 tool_call，再经过参数校验、策略判断和 WorkspaceBoundary，最后才有机会触达本地文件或进程。

03 / LIFECYCLE

一轮任务的
七个检查点。

下面不是概念图，而是 Runner 在一次 send / start 中反复执行的真实责任顺序。

01◎

INTAKE

校验非空任务，确定 workspace 与 Ask / Plan / Auto 模式。

输入与输出user text → ChatMessage(user)
02◌

CONTEXT

保留 system、任务身份和最近完整 turn，计算可用预算。

输入与输出messages[] → prepared context
03✦

REQUEST

ModelClient 发出 OpenAI-compatible 请求并消费流式 delta。

输入与输出messages + schemas → stream
04⌁

PARSE

把文本、reasoning、tool_calls 和 usage 组装成统一响应。

输入与输出delta chunks → ModelResponse
05⊙

POLICY

按 capability 与模式判断审批、提案、并行或串行。

输入与输出tool_call → allowed / pending
06▣

EXECUTE

本地工具在边界内执行，结果以 tool message 回填历史。

输入与输出validated args → ToolResult
07■

VERIFY / STOP

无 tool call 则 final；否则继续，或写入明确 RunState。

唯一终态FINAL · CANCELLED · STOP_*
tool result 回到 CONTEXT↺直到任务完成、被取消或触发安全终止条件

05 / CAPABILITIES

工具先声明，
再允许执行。

ToolRegistry 把模型的函数调用转换为本地能力，但每一层都可以拒绝不合法或越界的请求。

TOOL CONTRACT
Tool {
  name: string
  description: string
  parameters: JSONSchema
  capability: "read" | "write"
  execute(args) → ToolResult
}
01 registry lookup02 JSON decode03 schema validate04 execute / normalize
EXECUTION MATRIX
能力例子调度副作用
READlist / read / search可并行无写入
WRITEwrite / patch / delete串行需策略
COMMANDrun_command受限 argv宿主边界
GITstatus / diff / log工作区内证据读取
PATHWorkspaceBoundary

规范化路径、解析已有符号链接，拒绝 workspace 外部目标。

ARGS小型 JSON Schema

required、类型、枚举、长度和数值上下限由项目内验证。

RESULT结构化错误

UnknownTool、InvalidArguments、FilesystemError 等不会击穿主循环。

TEXT

内容流

content delta 只更新用户可见回答；桌面端按事件增量渲染，不把每个 token 拼成一大段重新发送。

REASONING

思考流

reasoning_delta 作为内部事件保留，默认不进入主对话气泡；需要展示时以折叠摘要呈现，避免泄漏 scratchpad。

TOOL CALL

调用聚合

按 provider 给出的 index 聚合函数名和 arguments；done 后才生成完整 ToolCall，参数不完整就进入协议错误路径。

RETRY

有限重试

请求在尚未产生可见输出时才重试；部分流已经交付后不重放，避免重复文本或重复执行。

07 / CONTROL

继续还是停止，
由程序决定。

Runner 的循环不是“让模型一直说”，而是每轮在多个安全检查点上做确定性判断。

AGENTRUNNER / STATE MACHINE deterministic gates
START→CHECK
cancel / deadline / budget→MODEL_REQUEST→DISPATCH
tool policy↺FINAL
任何节点→STOP_*唯一终态，携带原因和已完成证据
TERMINAL STATES
FINAL模型没有 tool_call，写入最终答复
STOP_MAX_STEPS达到配置上限；状态可继续
STOP_TASK_TIMEOUT整轮 deadline 到期，保留已完成变更
STOP_TOOL_ERROR_LIMIT连续或重复失败超过阈值
STOP_CONTEXT_BUDGET协议所需历史无法安全压缩
CANCELLED用户取消或 Ctrl+C
LOOP INVARIANT

工具结果回填消息后才允许下一次模型请求；没有结果，就没有下一轮。这样每一次继续都有事实依据。

08 / RECOVERY

失败不是黑屏。
失败也是一种状态。

错误被分层处理：能修正的交给模型，不能安全继续的交给终止状态，能恢复的留下快照和变更证据。

01 / TOOL

局部失败

工具捕获输入、文件系统和未知异常，统一返回 ToolResult.failure(kind, message)，模型可以据此改参数或换路径。

→ model can repair
02 / RUNNER

连续失败

按工具调用签名记录重复失败；连续错误达到配置阈值时停止，避免在同一个坏参数上无限循环。

→ STOP_TOOL_ERROR_LIMIT
03 / CHANGESET

变更保护

变更前记录文件基线，变更后计算 SHA-256；无冲突时可以 guarded rollback，有外部修改则拒绝覆盖。

→ review / rollback
04 / SESSION

进程恢复

JSON snapshot 保存 pending approval、TaskPlan、steps 和 messages；重新载入后从未完成边界继续，不重放已完成调用。

→ resume

主对话讲结果，
运行面板讲过程。

详细轨迹通过 JSONL 事件流送入右侧运行面板；主会话只保留阶段性、可读的工作摘要。

11 / BOUNDARIES

安全边界不是一句话，
是每个调用点。

这些是当前实现的真实约束，同时也是演示和后续隔离建设必须明确的边界。

01WorkspaceBoundary

路径拒绝越界

相对路径、绝对路径和符号链接都会经过统一解析，只允许落在当前 workspace。

02Policy / Mode

写入需要策略

Ask 等待批准，Plan 只读提出方案，Auto 也仍然经过 capability 策略。

03run_command

受限而非沙箱

命令使用字面 argv、超时、进程组终止和环境剥离；它不是 OS 级隔离。

04TraceWriter

证据默认脱敏

事件与 trace 分开保存，并对敏感 key 和已知 secret 值做脱敏处理。

!
运行建议

演示时使用不含凭据的隔离 workspace；任何 live provider、shell 或 Git 行为都应以运行面板和工作区 diff 为准。
