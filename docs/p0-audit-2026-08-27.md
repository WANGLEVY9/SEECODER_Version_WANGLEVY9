# P0 审计结论（2026-08-27）

## 结论

P0 的离线基座可以通过：它不使用 Agent 框架，主循环、本地工具、上下文裁剪、错误终止、配置隔离与 trace 均为本仓库自建。24 项确定性单元测试通过，且不需要真实模型 API。

这不是对真实模型成功率的声明。DeepSeek V4 Flash 的实际多轮工具调用、网络错误形态与费用仍须在 P1 的受控联调中验证。

## 已核对并通过

- 题目边界：仅使用普通 `openai` 客户端和模型原生 tool calling；没有 Agent SDK、框架或托管代码/文件工具。
- 主循环：有最终回答、最大步数、连续工具错误、模型失败和 Ctrl+C 五类可解释结束路径。
- 文件边界：相对路径、绝对路径和已存在符号链接均解析后检查；`.env` 文件不可通过文件工具读取或写入。
- 进程行为：命令有超时、进程组终止、敏感环境变量剥离，并用后台 drain 保证大量 stdout/stderr 不在内存中无限累积。
- 输入输出边界：文件读取有 1 MB 上限，写入有字符上限，命令和上下文输出有上限。
- 配置与日志：CLI 拒绝放在可编辑 workspace 内的 `.env` 和 trace 目录；trace 对已知密钥和常见敏感字段脱敏。
- 回归验证：`PYTHONPATH=src python3.12 -m unittest discover -s tests -v` 在本机通过 24 项测试。

## 仍然存在但已明确约束的边界

`run_command` 是本机 shell，不是 OS 级沙箱。`cwd`、黑名单和超时不能阻止熟悉 shell 的命令访问工作目录外的主机资源。因此演示和真实运行必须使用不含凭据的隔离 workspace；P1 会提供更受限的执行模式。该风险已在 README 和工具契约中明确，而非宣传为“完全沙箱”。

DeepSeek V4 Flash 默认思考模式下，工具调用后的每一次后续请求都必须携带原始 `reasoning_content`。P0 目前显式设置 `SEECODER_THINKING_MODE=disabled`，以建立可验证的非思考工具调用基线；完整思考模式支持是 P1 的首项工作。
